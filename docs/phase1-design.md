版本：v1.3　日期：2026-11-14
范围：**不碰游戏本体**。本阶段只解决"玩家画出来的形状，怎么算出一台说得通的发动机"。

## 0. 一句话结论

Flyout 的做法是**性能参数驱动**：玩家填压比、级数、涡轮压比、涵道比，性能几乎直接照着这些数走。
我们要做的是**几何驱动**：玩家填的是直径、级数、轴怎么连，压比和涡轮功由几何**算出来**，
算不出来的地方就报错（涡轮带不动、叶尖超速、涡轮吃不下落压比）。

这条路线的代价是要写一个真求解器，好处是它才是"造发动机"，而不是"调发动机"。
所以 mod 给两档：**简单模式**（涵道比/增压比/燃烧室温度/排气温度/尺寸六个输入）先让人上手，
**残酷模式**（完整几何）才是主菜（§7）。两档喂同一台机器时，设计点差 0.4%（§6.4）。

本阶段已交付一个能跑通全流程的原型（`JetForge/proto/`）。拿四台真实发动机做闭环：
J79 / J57 的 SFC 偏差 −7.2% / −4.0%，RD-33 −6.7%。J85 的 −29.5% 查下来是**手册数据自相矛盾**
（它标称 TIT 1253 K，但它的推力/流量/SFC 要求 1564 K），不是模型缺陷。
判据（§7.4）与油门×高度×马赫的预解网格（§7.5，270 点 0.2 s 建完、内插误差 <3.5%）都已经跑通。
剩下的是标定和落地。

## 1. Flyout 是怎么做的，以及它的边界

### 1.1 它的参数体系（已取证，见 `research/flyout_engines.md`）

Flyout 的涡轮编辑器按 **1–3 个 spool（轴）** 组织，每轴独立设：

| 项目 | 存档键 | 实测取值 |
| --- | --- | --- |
| 压气机级数 | `cs0/cs1/cs2` | 1–7 |
| 压气机压比 | `cpr0/cpr1/cpr2` | 1.45–13.48 |
| 涡轮压比 | `tpr0/tpr1/tpr2` | 0.05–0.78 |
| 叶尖马赫 | `mach` | 0.8（社区用 0.84 / 1.2） |

全局还有：`radius`（整机直径）、`bpr`（涵道比）、`tt4`（燃烧室温度）、`combustor`（燃烧室类型、
整数枚举）、`idle`（怠速油门）、`fan{radius,fpr,blade_count}`、`afterburner{tt7,throttle_threshold,bp_mixing}`、
`nozzle`、`hydraulic`、`alternator`。

### 1.2 它刻意省略掉的东西

对照我们的需求清单，Flyout **没有**：

- 压气机/涡轮的**直径**——只有一个整机 `radius` 和风扇的 `radius`
- **燃烧室形状与长度**——只有 6 个整数枚举
- **轴的连接关系**——spool 是"压气机+涡轮"的绑定单元，玩家不能把 HPC 接到风扇的轴上
- **加力喷油量**——只有目标温度 `tt7`
- 涡轮级数（游戏自己算）

所以 Flyout 本质上是一张"性能表"，玩家在表上调参。它甚至自己承认方向在变——
更新日志里有一句："Turbofan RPM is now independent of core RPM as it will be required by
the upcoming **engine building mode**"。也就是说官方自己也在往几何驱动走。

**这就是我们的空档。** 玩家要的是"我造了一台 1.2 m 风扇、8 级高压、双轴的发动机，它能推到多少"，
不是"我把压比填成 12 会怎样"。

### 1.3 可以直接借用的设计

- **Test Run Mode 式的实时读数**：改参数立刻看推力/流量/SFC/压比变化。这个交互必须抄。
- **参数分层**：Advanced Setup 打开后才出现细分项。我们也该有"简单模式/专家模式"。
- **红色警告机制**：总压比过高标红。我们做得更细——每个判据给一句话为什么不行。
- **引气/附件功率抽取**（`ex_bleed`/`hydraulic`/`alternator`）：从轴功率里扣比例，实现极便宜。

### 1.4 不要照抄的地方

- `tpr` 那个"数字越小抽功越多"的语义**反物理**。我们的涡轮落压比由功率平衡反解，玩家不该调它。
- `bpr` 直接当输入。我们的涵道比是几何算出来的**结果**（`BPR = (D_fan² − D_core²)/D_core²`）。

## 2. 现实发动机的经验公式体系

全部按 **SI 单位、一维准稳态** 组织。符号：`m` 流量，`T/t` 总温、`P/p` 总压，下标
0 来流 / 2 风扇后 / 3 压气机后 / 4 燃烧室后 / 5 涡轮后 / 7 加力后 / 8 喷口。

### 2.1 气体物性（不要用常数 1.4）

真实循环里燃气 `γ` 从 1.40 掉到 1.30 量级，忽略它会系统性高估涡轮功。

```
γ(T, far) ≈ 1.40 − 0.06·(T − 288)/1000 − 0.10·far
cp(T, far) ≈ 1004.5 + 0.15·(T − 288) − 900·far     [J/(kg·K)]
```

原型里 `gamma_of()` / `cp_of()` 就是这两个，比定常数 `CP_AIR` 在 1500 K 处差 5–8%。

### 2.2 标准大气

0–11 km：`T = 288.15 − 0.0065h`，`p = 101325·(T/288.15)^5.2559`
11–20 km：`T = 216.65`，`p = 22632·exp(−g(h−11000)/(287·216.65))`

KSP 不用真实大气，但**求解器必须按真实 ISA 算**，再由 KSP 的 `CelestialBody` 数据做一层映射，
否则同一台发动机在地球和海平面 Kerbin 上的自持边界会差很多。这一点在 KSP 落地章节展开。

### 2.3 进气道总压恢复

亚声速：`σ = 0.97 ~ 0.99`（外压式皮托管进气道取 0.99）
超声速（MIL-E-5008B，业界通用经验式）：

```
σ = 1 − 0.075·(M − 1)^1.35      （1 < M < 5）
```

这比"取一个常数"重要得多：M2.0 时 σ≈0.85，直接砍掉 15% 的可用压比。

### 2.4 轴流压气机：单级压比与温升

单级的核心是**叶尖线速度** `U = πDN/60` 和**载荷系数** `ψ = cp·ΔT/U²`：

```
ΔT_stage = ψ·U²/cp                              （载荷系数 ψ：现代 0.30~0.50，老式亚声速级 0.20~0.32）
π_stage  = (1 + ψU²/(cp·T_in))^(γ·η_poly/(γ−1)) （η_poly = 多变效率）
```

- 现代跨声速级：`U_tip = 400 ~ 460 m/s`，单级 `π = 1.4 ~ 1.8`
- 老式亚声速级：`U_tip = 250 ~ 320 m/s`，单级 `π = 1.15 ~ 1.3`
- 叶尖马赫上限：风扇 `1.0 ~ 1.3`（现代宽弦）、压气机 `1.0 ~ 1.1`（更高速会激波失速）
- 多变效率：`0.88 ~ 0.92`（现代）、`0.82 ~ 0.86`（1940–60 年代）
- 整机压比：`OPR = Π π_stage`；**温度是硬的**——末级出口 `T3` 超了，后面燃烧室的温升空间就没了

一台机器的转速不是自由变量：**每根轴的转速取该轴上所有叶轮的叶尖马赫限制中最低的那个**。

```
N_shaft = min_over_该轴叶轮( M_tip·a(T_ref)·60/(π·D) )
```

这条是整个模型里最"几何"的一条：换上大直径风扇，N1 立刻掉下来，LPT 就得更费力。

### 2.5 燃烧室

```
T4 = 目标出口总温（玩家输入或 FADEC 给定）
ṁ_f = ṁ3·cp·(T4−T3) / (LHV·η_b − cp·(T4−T3))
ΔP/P|燃烧室 = 3% ~ 5%（环形）/ 6% ~ 8%（环管、老式单管）
η_b = 0.98 ~ 0.995
```

- 煤油 `LHV = 43.0 MJ/kg`
- 贫油熄火上限 `f = ṁ_f/ṁ_air ≈ 0.068`（化学恰当比 0.068，富油侧更宽但会冒烟）
- **燃烧室形状在本模型里只影响两件事：总压损失和能否达到给定长度的完全燃烧**。
  这个映射关系见 §4.6。
- T4 上限：`1100 K`（1940s 无冷却）→ `1300`（1960s）→ `1600`（1970s 气冷叶片）→ `1750`（1990s 单晶+热障涂层）→ `2000+`（2010s 双层壁）

### 2.6 涡轮

涡轮不设"玩家压比"，由功率平衡反解。单级能力：

```
ΔT_stage = ψ_t·U²/cp        （涡轮 ψ_t = 2.4 ~ 3.4，比压气机大得多，因为燃气加速膨胀）
π_stage  = (T_out/T_in)^(−γ/((γ−1)·η_t))       η_t = 0.85 ~ 0.92
```

- 级数只约束"能不能吃掉所需的落压比/温降"，**不是上限判据**（这是原型 v0.1 踩过的坑）
- 涡轮叶尖速度通常比压气机更受限：`M_tip ≤ 0.95`（离心应力）

### 2.7 喷管

收敛喷管，临界压比 `NPR_crit = ((γ+1)/2)^(γ/(γ−1)) ≈ 1.893`：

```
若 P5/p0 ≥ NPR_crit   → 壅塞，M8 = 1，p8 = P5/NPR_crit，T_exit = Tt·2/(γ+1)
否则                  → 亚临界，p8 = p0，V8 = sqrt(2·cp·Tt·η_n·(1 − (p0/P5)^((γ−1)/γ)))

V8 = sqrt(2·cp·Tt·(1 − T_exit/Tt)·η_n)
A8 = ṁ / (ρ8·V8)          ρ8 = p8/(R·T_exit)
```

**喷管出口速度不能直接当推力用。** 壅塞时出口压力 `p8` 高于大气压，那部分压差在喷管壁面上
实实在在地推着发动机往前，必须算进去。原型一版漏了它，涡喷单位推力整整低了 25%：

```
F_nozzle = ṁ·V8 + (p8 − p0)·A8
```

J79 实算：`p8 = 241 kPa`、`A8 = 0.118 m²`，动量项 40.4 kN + 压力项 16.5 kN = 56.9 kN，
对上真实 52.8 kN。

**三种喷管型式（已实现，对应 `nozzle.kind`）**

| 型式 | 几何 | 高落压比时的行为 | 典型用途 |
|---|---|---|---|
| `converging` | 喉道=出口，面积固定 | 壅塞后欠膨胀，`p8 = P5/1.893`，压力推力大；**加力时喉道吃不下流量** | 无加力的涡喷/涡扇 |
| `variable` | 收敛，喉道面积可调 | 压力推力同收敛解，但喉道跟着流量走，**不会被憋住** | 多数带加力的二代机 |
| `converging_diverging` | 固定面积比 A9/A8，按设计点完全膨胀定尺寸 | 出口超声速，`p8` 由面积比反解；落压比低于设计值时**过膨胀、喷流分离**，退回收敛解 | 三代以后加力机、超声速机 |

面积–马赫关系（收扩反解马赫数时用，超声速支二分求解）：

```
A/A* = (1/M)·[ (2/(γ+1))·(1 + (γ−1)M²/2) ]^((γ+1)/(2(γ−1)))
p8   = P5 / (1 + (γ−1)M8²/2)^(γ/(γ−1))
```

实现要点：`Gas.NozzleFlow(mdot, pt, tt, p0, η_n, kind, aThroat, areaRatio)` 返回 `Ve/Ae/Pe/Thrust/MachE` 与三个标志
`Choked / Separated / BackPressure`。`aThroat`（A8）与 `areaRatio` 都由设计点反解并存进 `DesignConstants`，
所以非设计点算的仍然是这台机器的真实几何，而不是每次重新"最优设计"。

**实测（JF-1 核心机，喷管按干态定尺寸后开加力 far_ab=0.03）**

```
型式                  面积比  出口Ma   干态推力   加力推力   加力SFC   憋住  分离
Converging             1.05    1.00     83.60     98.03    0.0970     是    否
Variable               1.05    1.00     83.60     98.03    0.0970     否    否
ConvergingDiverging    1.05    1.26     83.99     98.94    0.0961     否    否
```

→ 结论：**这台机器核心喷管落压比只有 ~2，收扩带来的增益只有 0.9%**；落压比越高（总压比越大、加力越猛）增益越大。
真正被这个模型抓住的是**收敛喷管被憋住**：干态定的喉道过不了加力的流量，`BackPressure=true`，
判据会直接说"真实加力推力会低于本模型读数"。

### 2.8 推力

```
F_core  = ṁ_core·(1+f)·V8_core + (p8_core − p0)·A8_core − ṁ_core·V0
F_byp   = ṁ_byp·V8_byp + (p8_byp − p0)·A8_byp − ṁ_byp·V0
F_net   = F_core + F_byp − D_nacelle
D_nacelle = 0.5·ρ0·V0²·A_front·C_D      （C_D ≈ 0.08）
```

**注意**：`Σṁ(V8 − V0)` 已经把冲压动量扣过了，不要再额外减一次 `ṁ·V0`。
原型里犯过这个错，高空大马赫下净推力被白吃掉 30%。

### 2.9 单位推力与耗油率（校验标尺）

```
F/ṁ = (1+BPR)·[ 加权平均(V8 − V0) ] + Σ[(p8 − p0)·A8]/ṁ        [N/(kg/s)]
SFC = ṁ_f·3600 / F_net                      [kg/(N·h)]
1 kg/(N·h) = 9.8066 lb/(lbf·h)
```

真实量级：

| 机型 | 推力 | 流量 | 单位推力 | 干态 SFC |
| --- | --- | --- | --- | --- |
| J79-GE-17（涡喷，1955） | 52.8 kN | 77 kg/s | **686** | 0.84 lb/(lbf·h) |
| J57 族 / JT3C-7（涡喷，1953） | 53.5 kN | 81.7 kg/s | **655** | 0.785 |
| J85-GE-13（涡喷，1957） | 16 kN | 24 kg/s | **667** | 1.24 |
| RD-33（涡扇，1981） | 50 kN 干 / 81 kN 加力 | 76 kg/s | 658 | 0.735 / 1.85 |
| CFM56-7B（涡扇） | 117 kN | 350 kg/s | 334 | 0.60（巡航） |
| F110-GE-100（涡扇，加力） | 76 kN 干 | 120 kg/s | 630 | 0.70 |

**单位推力是最硬的约束**：它几乎只取决于 T4 和 OPR，与玩家怎么摆级数关系不大。
涡喷落在 650–720 N/(kg/s)（≈ 65–73 lbf/(lb/s)），涡扇按 BPR 往下掉。
原型实测见 §6.2。

一个必须记住的兼容性陷阱：**文献里的 TIT 极不可靠**。J79 标称 TIT 1210 K，
但用 77 kg/s、52.8 kN、OPR 13.5 反推，压气机功要吃 414 kJ/kg，涡轮出口只剩 843 K，
收敛喷管壅塞时 `V8 = sqrt(γR·0.833·843) = 522 m/s`，动量+压力推力合计 604 N/(kg/s)——
比真实 686 低 12%。要么真实 TIT 是 ~1300 K，要么那三个数里有一个是别的状态点的。
**结论：用推力/流量/SFC 三角自洽去校验，别把 TIT 当输入真值。**

这条 2026-11-14 已经被原型量化了（见 §6.3）：把三台老发动机的手册 SFC 反推成燃油比，
再反解出它要求的 T4，J79 要 +151 K、J57 要 +132 K、J85 要 +311 K，而 RD-33（现代机，
TIT 测量规范）只差 −71 K、判定可用。**老手册的 TIT 系统性偏低 130–310 K。**

### 2.10 尺度效应：机器做小了，效率就是要差

同一年代、同一套设计，把发动机等比缩小，效率会掉。两个原因，都是"不随尺寸等比缩小"的量造成的：

**1) 叶尖间隙占比。** 间隙是制造公差决定的绝对值（约 0.3–0.5 mm），不会因为叶片变短就变薄：

```
clr   = max(clr_min, 0.008·h)              h = (D/2)(1 − 轮毂比)  叶高
Δη_间隙 = k_clr · (clr/h − 0.008)          k_clr ≈ 1.3   （大于 0 才罚）
```

**2) 叶片弦长雷诺数。** 损失 ∝ Re^(−n)，n ≈ 0.2：

```
c   = h/2.5                                （弦长，展弦比约 2.5）
Re  = ρ·U·c/μ                              μ 用 Sutherland 式
Δη_Re = (1 − η)·[(Re_ref/Re)^0.2 − 1]      Re_ref ≈ 3×10⁵，Re ≥ Re_ref 不罚
```

两项都是**只在低于基准时才罚、不高于基准时不给奖励**——所以大发动机不受影响，
小发动机被扣。原型里 `scale_eta()` 干这件事，`CycleResult.scale` 存每个部件的明细
（叶高、间隙占比、Re、基准效率、实际效率）。

**它有多大？** 实测：J79 各级 0.00%，J85 高压压气机 0.67%，RD-33 高压压气机 0.06%。
**结论：尺寸效应只能解释个位数百分点的 SFC 差距，解释不了 30%。**
谁要是跟你说小涡喷 SFC 差 30% 是"尺度效应"，那是拿它当万金油。

## 3. 求解链（这就是 mod 的核心算法）

两个模式，一套代码：

### 3.1 设计点：`solve_design_point(design)`

输入：全套几何 + 技术年代 + 设计工况（`design_mach`/`design_alt`）。

1. **转速**：按 §2.4 求每根轴的设计转速（各轴叶轮取最小叶尖马赫）
2. **逐级压缩**：风扇 → LPC → HPC，每级算 `π_stage`、`ΔT_stage`，得到 `T3`、`P3`、`OPR`、`FPR`
3. **燃烧室**：烧到 `T4`，算 `f`、`P4`
4. **轴功平衡**：每根轴上 Σ涡轮功 = Σ该轴压气机/风扇功，反解每级涡轮的 `ΔT` 与 `π`
5. **流量闭合**：`ṁ_core` 由涡轮导向器壅塞给，`ṁ_air = ṁ_core·(1+BPR)`
6. **推力**：喷管 + 加力

错误判据（任何一条命中就报错，不是警告）：

| 判据 | 玩家看到的话 |
| --- | --- |
| 轴上有负载无涡轮 | "轴 2 上有 5.37 MW 的压气机负载，但没有涡轮驱动它 → 转不起来" |
| 涡轮级数不足 | "LPT 级数不足：需要 ΔT=325K，4 级只能提供 258K" |
| 涡轮落压比超限 | "高压涡轮需要 π=4.2，2 级单级上限 2.4 达不到" |
| `T4 ≤ T3` | "压比太高，压气机出口 1650 K 已经超过燃烧室设定温度" |
| 涡轮出口总压 < 环境 | "涡轮出口 100.3 kPa 低于环境 101.3 kPa：喷管倒流" |

### 3.2 非设计点：`solve_offdesign(design, alt, mach, throttle)`

结构抄 AJE 的 `SolverJet.CalculatePerformance`（20 次迭代），但修补了它两处硬伤：

```
迭代（收敛判据 |Δπ| < 1%）：
  T3 = Tt1·π^((γ−1)/(γ·η))
  燃烧室烧到 T4_cmd → f
  涡轮出口：T5 = T4·TTR，但如果 P5 掉到大气以下，就改成"少抽功、T5 抬高"
  涡轮功 w_t = cp·(T4 − T5)
  风扇先加热全部空气：ΔT_fan = w_fan/((1+BPR)·cp)
  T3_new = Tt1 + ΔT_fan + w_comp/cp
  π_new  = (T3_new/Tt1)^(γη/(γ−1))
```

迭代完再算：`ṁ_core = choked(a_turb, P4, T4)`、风扇、喷管、推力、转速反推。

**AJE 的两个硬伤，我们已经修掉：**

1. **固定 TTR 在低功率下会算出 `P5 < p_amb`**——物理上不可能。真实发动机这时喷管不壅塞、涡轮少抽功。
   修法：`T5 = max(TTR 给的, 喷管背压允许的)`，让低功率点自动收敛到"刚好不倒流"。
   修完之后慢车 N2 自然落到 59.8%（之前是 75.8%，明显不合理）。
2. **流量与设计点自洽**：AJE 用固定的 `turbineAreaRatio`；我们让涡轮喉道面积**由设计点反解**
   （`a_turb = ṁ_core·√T4/(Pt4·choke)`），保证"进气道能吃的"和"涡轮能过的"是同一个数。

### 4.6 加力燃烧室

| 参数 | 单位 | 说明 |
| --- | --- | --- |
| 是否配备 | bool | 不配则加力段不可用 |
| **喷油量** | 油气比 far_ab（相对主流空气） | **玩家直接拧这个**，上限 0.045；温度由它反算 |
| 出口温度 T7 | K | 与喷油量二选一；上限 `min(max(T4_limit+400, 1800), 2100)` |
| 喷油环形式 | 环形 / 喷雾环 / 突扩 | 决定 `η_ab` 与 `ΔP/P` |

| 形式 | 代码 kind | η_ab | ΔP/P |
| --- | --- | --- | --- |
| 环形 | `ring` | 0.930 | 0.030 |
| 喷雾环 | `spray_ring` | 0.950 | 0.040 |
| 突扩 | `dump` | 0.900 | 0.055 |

**为什么加力温度上限比 T4 高 400 K**：加力段没有涡轮叶片挡在燃气里，唯一的热约束是喷管和
筒体隔热。1940s 都给到 1800 K，现代到 2100 K。

**加力只烧核心流**，所以 `BPR` 越大，同样喷油量带来的推力增益越小——这是玩家最容易踩的坑：
给一台 BPR 5 的大涵道机装加力，烧同样的油只多 8% 推力，还白搭重量。
实测（§6.3）：BPR 2.75 的涡扇 far_ab 0.02 只 +14.3%，涡喷同条件 +38.2%。

### 4.7 喷管

| 参数 | 枚举 | 说明 |
| --- | --- | --- |
| 形式 | 固定收敛 / 可变面积 / 收扩(C-D) | 本阶段只实现收敛，另两种留接口 |
| 出口面积比 | — | 仅 C-D 用 |

**带加力的发动机必须用可变面积喷管**：加力后 `P5/p0` 升到 5–6，固定收敛喷管把多余压力
全变成白丢掉的欠膨胀损失。原型会在玩家"配加力但选固定喷管"时给警告。

加力喷油量的自洽约束：

```
T7 = T5 + ṁ_f,ab·LHV·η_ab / (ṁ_core·(1+f)·cp)
约束：T7 ≤ T7_max(材料)；ṁ_f,ab ≤ 氧气允许量（混合后 f_total ≤ 0.068）
```

给"喷油量"而不是只给温度，是为了让玩家能算出**能烧多久**——这直接决定加力持续时间。

## 5. 输出读数（玩家在编辑器/飞行里看到什么）

### 5.1 设计点读数

推力、净推力、进气量（总/核心/涵道）、涵道比、总增压比、风扇压比、单位推力、SFC、
T3/T4/T5/T7、每级压比与温升、各轴功率（MW）、涡轮落压比、喷管压比、是否壅塞。

### 5.2 N1 / N2 / N3 的语义

必须和 KSP 原生习惯对齐，否则玩家看不懂：

| 轴数 | 命名 |
| --- | --- |
| 1（涡喷/单转子） | 只显示 **N2**（与 AJE 一致，老玩家也习惯） |
| 2 | N1 = 低压轴（风扇+LPC+LPT），N2 = 高压轴（HPC+HPT） |
| 3 | N1 = 风扇，N2 = 中压（LPC+IPT），N3 = 高压（HPC+HPT） |

`N_x% = 该轴当前转速 / 该轴设计转速 × 100`。设计点即 100%，慢车约 60%，超转 >105% 报警。

**轴号不是写死的**：`spool_readout()` 只看"风扇挂在哪根轴上"。风扇和 LPC 同轴 → 双轴；
LPC 单独一根轴 → 三轴；没有风扇 → 单轴。玩家怎么连轴，读数就怎么变。

**涡喷的 N1 不是"风扇转速"**——没有风扇时它就没有 N1，这也是单轴显示 N2 的原因。

### 5.3 能否自持（self-sustaining）

逐条判，全部满足才算：

```
1. 涡轮功 ≥ 该轴全部压气机/风扇功 + 附件抽取          （功率平衡，迭代里已保证）
2. 涡轮出口总压 ≥ 环境总压                              （不被背压倒流）
3. T4 ≤ 该年代材料上限
4. 各轴转速在设计转速的 100%±5% 内（地面静止满油门）
5. 燃烧室油气比在贫油熄火限内
6. 净推力 > 0
```

任何一条不满足 → 报出**具体是哪一条、差多少**。"能不能自持"这个问题玩家最常问，回答必须带数字。

## 6. 校验结果（原型实测）

### 6.1 方向性（教科书级别的定性验证）

| 实验 | 结果 | 判定 |
| --- | --- | --- |
| HPC 级数 4→16 | OPR 5.65→34.73，推力 78.8→**76.5** kN，SFC 0.0621→**0.0414** | ✅ 固定 T4 下提 OPR 改善 SFC 而非推力 |
| T4 1100→1600 K | 推力 58.1→86.2 kN，SFC 0.0398→0.0561 | ✅ 提温增推但费油 |
| 风扇 0.9→1.5 m | BPR 1.11→4.85，N1 9027→5416 rpm，SFC 0.067→0.042 | ✅ 大风扇省油但 N1 掉下来 |
| 风扇加到 1.7 m | "LPT 级数不足：需要 ΔT=325K，4 级只能提供 262K" | ✅ 大风扇需要更多 LPT 级 |
| 三轴但 IPT 缺失 | "轴 2 上有 5.37 MW 压气机负载但没有涡轮驱动" | ✅ |
| HPC 叶尖 0.40→0.60 m | OPR 6.98→19.86，推力 80.3→81.2 kN | ✅ 同转速下大直径=高叶尖速度=高单级压比 |
| 同一核心机涡喷 vs 涡扇 | 涡喷 OPR 16.5 / SFC 0.083 vs 涡扇 OPR 11.7 / SFC 0.053 | ✅ 涡扇靠加大流量换效率 |

### 6.2 定量（与真实发动机比）

用 `JetForge/proto/validate.py` 做闭环，分三步，因为一步做不干净。

**第一步：拟合 OPR，看 SFC。** 给定真机的级数/直径/轴，用它真实的 OPR 反解 `psi_scale`
（这个倍率乘在 `tech.compressor_psi` 上，反映"这台机器的级载荷打得有多满"），然后拿 SFC 对账。
SFC 和单位推力都与流量无关，所以不需要去凑真实流量。

| 机型 | OPR | psi_scale | SFC 原型 | SFC 真实 | 偏差 | 单位推力原型 | 真实 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| J79-GE-17 | 13.50 | 0.662 | 0.779 | 0.840 | **−7.2%** | 609 | 686 |
| J57 族 / JT3C-7 | 12.50 | 0.677 | 0.754 | 0.785 | **−4.0%** | 563 | 655 |
| J85-GE-13 | 8.30 | 0.964 | 0.875 | 1.240 | **−29.5%** | 677 | 667 |
| RD-33 | 21.00 | 0.690 | 0.686 | 0.735 | **−6.7%** | 756 | 662 |

`psi_scale` 落在 0.66–0.96，乘上各年代的 `compressor_psi` 后实际 ψ = **0.21–0.31**（J79 0.21、
J57 0.22、J85 0.31、RD-33 0.26）。这正是低载荷老式压气机的量级——J79 用 17 级才做到 13.5，
每级压比 1.165，本来就该这么低。

**第二步：把手册数据自己体检一遍。** 燃油比只由 `T4 − T3` 决定，而 `T3` 由 OPR 决定——
所以"手册 SFC 要求的燃油比"会反过来给出一个 T4 要求值。拿它跟手册 TIT 一比，就知道手册的 TIT 能不能用：

| 机型 | far 原型 | far 手册 | 比值 | TIT 手册 | **T4 要求** | 差 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| J79-GE-17 | 0.01344 | 0.01632 | 0.82 | 1210 | **1361** | +151 | TIT 偏低 |
| J57 族 / JT3C-7 | 0.01202 | 0.01456 | 0.83 | 1143 | **1275** | +132 | TIT 偏低 |
| J85-GE-13 | 0.01678 | 0.02342 | 0.72 | 1253 | **1564** | +311 | TIT 偏低 |
| RD-33 | 0.02187 | 0.02054 | 1.06 | 1680 | 1609 | −71 | ✅ 可用 |

**这是本轮最有用的结论**：三台 1950 年代发动机的手册 TIT 系统性偏低 **130–310 K**，
而 RD-33（现代机，TIT 测量规范）对上了。所以 §2.9 那条"TIT 不可靠"不是猜测，是算术。

**第三步：尺度效应。** 按 §2.10 的公式算各部件折减：

| 机型 | 部件 | 叶高 mm | 间隙占比 | 弦长 Re | η 基准 → 实际 | 共罚 |
| --- | --- | --- | --- | --- | --- | --- |
| J79 | HPC | 52.3 | 0.80% | 471 000 | 0.860 → 0.860 | 0.00% |
| J79 | HPT | 122.5 | 0.80% | 1 202 000 | 0.820 → 0.820 | 0.00% |
| J85 | HPC | 30.9 | 1.13% | 275 000 | 0.860 → 0.853 | **0.67%** |
| J85 | HPT | 73.5 | 0.80% | 420 000 | 0.820 → 0.820 | 0.00% |
| RD-33 | HPC | 41.2 | 0.85% | 812 000 | 0.900 → 0.899 | 0.06% |

大机器完全不受影响，小机器被扣 0.67%——**尺度效应是真的，但它只有零点几个百分点，解释不了 30%。**

**那 J85 的 −29.5% 到底是什么？** 不是模型缺陷，是那组手册数字彼此矛盾：
J85 要求 far = 0.0234，在 OPR 8.3 下对应的 T4 是 1564 K，而它标称 1253 K。
**同一个规格表里，推力/流量/SFC 跟 TIT 差了 311 K。** 这段数据不能当靶子用。
（顺带：J85 那一行在维基百科里本来就是混了 -13 和 -21A~C 两个亚型的数据，OPR 8.3 明确标的是 -21。）

**这条经验值得写进 mod 的校验流程**：任何一组手册数据，先用"燃油比反解 T4"过一遍，
对不上的就别拿来标定——否则你会把好模型改坏。

### 6.3 设计点 / 非设计点一致性

| 项 | 原型 | 真机参考 | 判定 |
| --- | --- | --- | --- |
| 满油门地面静止推力 | 非设计点 86.14 kN vs 设计点 82.21 kN | — | 4.6%，迭代容差 |
| 慢车 N2 | 59.8% | 典型 58–62% | ✅ |
| 慢车推力占比 | 9.31 / 86.14 = 11% | 典型 5–10% | 略高 |
| 11 km / M0.85 满油门推力 | 25.67 kN（地面 30%） | 同级 25–35% | ✅ |
| 11 km / M0.85 SFC | 0.0847 kg/(N·h) = 0.83 lb | 同级 OPR 11–16 机约 0.7–0.9 | ✅ |

**加力**——注意加力只烧**核心流**，所以同样喷油量下涵道比越大增益越小。同一台核心机：

| far_ab | T7 (K) | 推力 | 相对干态 | SFC lb |
| --- | --- | --- | --- | --- |
| 0（涡喷干态） | 842 | 91.6 kN | — | 0.739 |
| 0.010 | 1220 | 110.6 kN | **+20.8%** | 1.089 |
| 0.020 | 1589 | 126.6 kN | **+38.2%** | 1.370 |
| 0.040 | 1800（触上限） | 134.8 kN | **+47.2%** | 1.514 |

| far_ab | T7 (K) | 涡扇（BPR 2.75） | 相对干态 | SFC lb |
| --- | --- | --- | --- | --- |
| 0（涡扇干态） | 1085 | 86.1 kN | — | 0.507 |
| 0.010 | 1452 | 92.9 kN | +7.8% | 0.692 |
| 0.020 | 1800（触上限） | 98.5 kN | +14.3% | 0.855 |

真实 J79：干 52.8 → 加力 80 kN 是 **+51.5%**，加力 SFC 1.965 lb。原型涡喷 +47.2% / 1.51 lb：
推力增益差 4 个百分点（我们的加力温度顶到 1800 K，真实 J79 加力约 2000 K），SFC 偏低 23%——
和 §6.2 那 5% 的循环乐观是同一个方向，加力段因为 η_ab 取 0.95 而更明显。

**加力的两条驱动语义要分清**（代码里已经分开）：
- **设计态**：玩家填 `far_ab`（喷油量），由它反算 T7 —— 这是 mod UI 的输入；
- **飞行态**：KSP 给的是油门杆，所以 `offdesign` 用 `ab_frac`（0..1 向"加力最高温"插值）——
  两者都保留，`ab_fuel_ratio > 0` 时覆盖 `ab_frac`。

**已知偏差的归因**：
- **J85 那 −29.5% 不是模型问题，是手册数据问题**（§6.2 第二步证过：要 1564 K 才配得上它的 SFC）；
- 加力段推力增益 +47.2% 对真实 +51.5%，差的那 4 个点在加力温度上限（我们 1800 K，J79 约 2000 K）；
  加力 SFC 偏低 23%，因为 `η_ab = 0.95` 且没算加力后喷管面积调节的损失；
- 其余三台在 −7.2% ~ −4.0%，同向偏低——说明本模型的循环效率整体偏乐观一点点（约 5%），
  这是可接受的系统性偏差，KSP 里玩家也不会拿它跟手册对到小数点。

### 6.4 两档模式交叉验证（同一台机器，两种输入方式）

用一台 1970 年代双转子涡扇（JF-1）做闭环：残酷模式按几何搭，简单模式只喂
`bpr=2.75 / opr=11.73 / t4=1500 / D=1.2 m` 四个数（OPR 与 BPR 由残酷模式的结果回填，
不是手调的）。

**逐点核对过归因**：两档的增压比几乎完全一致（11.73/12.18、13.51/13.91、20.36/20.56、9.29/9.72），
偏差全部来自**流量**。而流量偏差的方向在低空和高空是相反的，因为两档的流量约束不同：

- 简单模式走换算流量守恒 `ṁ√θ/δ = const`；
- 残酷模式走**涡轮壅塞** `ṁ = f(A_turb, pt4, T4)`，而 `pt4 ∝ p0·OPR`，所以 OPR 一升流量就跟着涨。

高空那 30% 的差距，**错的是残酷模式**：它用**物理转速**反解，11 km 上物理 N2 仍是 101%，
换算转速 `N/√θ` 已经到 **117%**（θ=0.752），早就跑出压气机特性线了，流量被虚抬约 35%。
判据里的换算转速一条（§7.4）正是把这个坑标出来的。参照真实数据：CFM56 级机器巡航推力
约为海平面的 20%，简单模式的 28% 比残酷模式的 41% 更接近。

低空 M0.85 那 +10% 反过来是简单模式偏高，原因同上（换算流量守恒没算冲压下的流量重分布）。
两档都在 ±10% 以内（海平面）或同向偏低（高空），目前作为"同一台机器的两种近似"是可接受的，
**修正方向已明确**：残酷模式把换算转速上限（105%）接进求解器，让 OPR 与转速互相约束。

## 7. 两档设计模式、判据与性能网格

进气道与喷管是 mod **后期**才碰的东西（它们决定"这台发动机装到飞机上之后还能剩多少"），
在那之前必须先把**核心机**弄对。所以 mod 提供两档，玩家自己选投入多少耐心。

### 7.1 两档是什么关系

| | 简单模式 | 残酷模式 |
| --- | --- | --- |
| 玩家要填 | 涵道比、增压比、燃烧室温度、排气温度、风扇直径、技术年代 | 全套几何：风扇/压气机/涡轮的直径·级数·轴分配、燃烧室形式、加力、喷管 |
| 求解器 | `simple.py`，能量平衡 + 统计关系 | `jetforge.py` + `offdesign.py`，逐级求解 |
| 单点耗时 | ~0.1 ms | ~0.7 ms |
| 能查的判据 | 温度、燃烧、喷管、换算转速 | 全部，含喘振裕度/叶尖马赫/轴平衡 |
| 定位 | 上手、快速出机、飞行性能足够 | mod 的主要方向 |

**简单模式不是"物理缩水版"**。它冻结的是*信息*，不是*物理*：给定 T4 与涡轮温比，
增压比依旧由"涡轮功 = 压气机功 + 风扇功"这条平衡算出来，而不是照抄输入。
输入里的 OPR 只用来**反解设计点的涡轮温比**，之后增压比就自己长了——这才解释得通
为什么降油门时增压比会掉到 3~4（真实 J79 慢车正是 3.5 上下）。

### 7.2 简单模式的算法（六个数怎么变成一条曲线）

输入：`bpr, opr, t4, t_exhaust, diameter, tech`。

1. **设计点定三件事**：T2/T3（由 fpr 与 opr 定）→ 能量平衡得 `ttr = T5/T4`、
   `fc = W_fan/W_comp`、`ṁ_d`（台架面马赫 0.5 折出的吸入量）。
2. **风扇压比用统计式**：`FPR ≈ 1.32 + 0.66/(1 + 0.38·BPR)`
   （BPR 0→1.98、0.6→1.86、2.75→1.64、5→1.55、9→1.47，精度按 ±10% 声明）。
   本来试过"旁路/核心两股射流速度协调"来定 fpr，给 BPR 2.75 算出 2.64（真机约 1.6），
   直接把 T2 抬过头、涡轮功不够，已废弃。
3. **非设计点冻结 `fc` 而不是 fpr**。冻结 fpr 时慢车风扇仍按设计压比吃功、涡轮供不起，
   增压比会被压到 1.x 而崩掉；冻结 fc 则风扇功随涡轮功一起退。
4. **涡轮温比在低功率必须放开**。恒定 TTR 到慢车会让涡轮抽走全部压头、喷管拿不到压力，
   推力精确等于 0（数学结论，不是 bug）。所以
   `ttr_cmd = ttr + (0.78 − ttr)·(1 − 油门)^1.5`，物理依据：慢车膨胀比只有设计值的 1/3~1/2。
5. **油门 → T4 取平方**。线性映射会让 15% 油门就把 T4 顶到 750 K、推力跳 23%，
   而 J79 在 N2 66% 只有约 8% 推力。
6. **流量走换算流量守恒** `ṁ = ṁ_d·(pt0/pt0_d)·√(Tt0_d/Tt0)·n_frac`。
   曾经写成"按面马赫积分"，在 M0.85 海平面会把流量算到设计值的 1.95 倍（真实约 1.48）。

**标定台账**（海平面静止，1970s 技术档）：

| 构型 | 原型 | 真机 |
| --- | --- | --- |
| 涡喷 干态 0.74 m / OPR 13.5 / T4 1210 | 77.4 kg/s、52.3 kN、0.72 lb | J79：77 kg/s、52.8 kN、0.84 lb |
| 同机 + 加力 far_ab 0.03 | 79.9 kN | J79 加力：80 kN |
| 涡扇 1.7 m / BPR 6 / OPR 30 | 408.7 kg/s、119.3 kN、0.0295 | CFM56 级：~0.030 |
| 涡扇 1.0 m / BPR 0.6 / OPR 22 | 88.7 kN、0.0668 | F404 级 |

油门扫描（涡喷）：0%→OPR 3.26 / 3.5 kN（6.7%）；30%→4.27 / 12.5 kN；
60%→6.50 / 26.0 kN；85%→10.15 / 41.3 kN；100%→13.50 / 52.3 kN。

### 7.3 残酷模式就是 §3 那两个求解器

没有额外的东西。`Engine(design)` 会自动按类型选后端，两者的输出都整理成同一套字段，
所以判据和网格对两档一视同仁。

### 7.4 判据（`criteria.py`）

判据分两级：**FAIL**（这台机器不可能按这个状态工作）、**WARN**（能工作但不合理）。
每条都带数值、限值、部位，UI 上直接可以做成红/黄/绿。

| key | 判什么 | 限值来源 |
| --- | --- | --- |
| `*.overspeed` | 物理转速 / 超转线 | 105% |
| `*.ncor` | **换算转速** N/√θ | 105%，见下 |
| `*.tipmach` | 叶尖相对马赫 | 风扇 1.25、压气机 1.05、涡轮 1.15（技术档） |
| `*.surge` | 喘振裕度 `SM = φ/φ_stall − 1` | 要求 ≥15%，φ_stall 风扇 0.32、压气机 0.38 |
| `*.phi_high` | 流量系数过大（流道对流量的反向判据） | 风0.70、压气机 0.75 |
| `temp.t3` | 压气机出口总温 | 900 K（盘/叶片材料） |
| `temp.t4` | 涡轮入口总温 | 技术档上限，无冷却时再夹 1250 K |
| `temp.egt` | 排气温度 T5 | 0.68×T4 上限 |
| `temp.t7` | 加力出口 | `min(max(T4上限+400,1800),2100)` |
| `burn.lean/rich` | 主燃油气比 | 熄火 0.0045、富油 0.070 |
| `nozzle.npr` | 喷管压比 | <1 判倒流；固定收敛喷管 >6 警告 |
| `shaft*.balance` | 每轴涡轮功 vs 负载 | 差 2% 内算平衡 |
| `thrust` | 净推力 ≤0 | 直接 FAIL |

**两条判据的诚实说明**：

- `surge` 用的是**流量系数的静稳代理**，不是真的压气机特性线。它能抓"流道对着这个流量太窄/太宽"
  这类几何错配，**不能**替代特性线上的喘振边界。UI 上要标明它是估算。
- `ncor` 换算转速是**用来抓模型自己犯错**的，不是抓玩家的。残酷模式用物理转速反解，
  高原上会给出 117% 换算转速（§6.4），这条判据会直接标红——这是它该干的事。

### 7.5 性能网格：飞行中不求解，只查表

飞行中每个物理帧都跑一次循环求解是不现实的（KSP 里一台飞机可能挂 8 台发动机）。
所以设计态一次性预解一张 **油门 × 高度 × 马赫** 的立方表，飞行中三线性内插。

- 体量：6 高度 × 9 马赫 × 5 油门 = 270 点。残酷模式 **0.2 s** 建完，简单模式 **0.0 s**。
- 每点存：推力、SFC、进气量、燃油流量、N1、N2、EGT、有效性（求解失败的点标掉）。
- 内插精度实测：+0.7% / +0.7% / −3.3%（海平面 / 6 km / 11 km），够用。
- 越界按边界夹（飞到表外不会炸，但也不要指望准）。
- 可存成 JSON / CSV，跟存档一起走——玩家换个引擎不用重算。

热力图是同一张表的可视化（PIL 手绘，本机没有 matplotlib）：每个油门一张子图，
横轴马赫、纵轴高度、颜色是所选量，失败格画暗红。产出：

| 文件 | 内容 |
| --- | --- |
| `out/brutal_thrust.png` / `out/brutal_sfc.png` | 残酷模式 JF-1 |
| `out/simple_thrust.png` / `out/simple_sfc.png` | 简单模式同机 |
| `out/thrust_map.png` / `out/sfc_map.png` | 早期版本，保留 |

形状是对的：推力随高度降、随油门升；海平面低马赫段随马赫上升（冲压增益），
高空段随马赫下降（温度升高、换算转速掉）。油门 30% 那张图右下角的暗红格
（0 km / M1.5）不是画错了——高马赫、低油门时冲压阻力已经超过净推力，
发动机确实推不动自己，判据里也是 FAIL。

### 7.6 已知缺口（都写在这里，别以为是完成了）

1. ~~残酷模式的高原推力仍偏乐观约 15%~~ **已量化并改过两次，见 `phase2-mod.md` §23**：
   换算转速上限接进去以后 11 km 两档差从 30% 收到 19.5%，再把换算流量—转速律从 `nc²` 改成线性
   （运动学依据：定通道面积、Ca/U 不变时 ṁ ∝ U）后收到 **12.3%**；剩下这 12% 是结构性的——
   简单模式没有特性线，做不出"高空换算转速抬到 1.05 → 换算流量 +9%"这件事。
   **绝对衰减比仍无真机高空数据可校**，所以停在 1.30×δ，不再往下猜；
2. 简单模式没有几何，所以叶轮/流道类判据直接跳过并如实标注；
3. `hub_tip_ratio` 目前只影响尺度效应折减与判据，**不影响推力/增压比/SFC**（流量由进气面积定）；
4. 简单模式内部固定按"风扇+核心"两条流路算，**单轴涡喷的 N1/N2 是等效读数、同步变化**
   （`simple.py` 会给这条 warning）；真实转速要等残酷模式；
5. 判据只覆盖核心机。进气道总压恢复、喷管面积匹配、附件功率抽取都留到后期。

### 7.7 换算转速与换算流量（这是"像真"和"像样"的分界线）

**为什么必须做这一步**：压气机特性线的横轴是**换算转速** `N/√θ`，不是物理转速。
原始的残酷模式用物理转速反解流量，于是 11 km 满油门时物理 N2 仍有 101%，换算后 117%——
早就跑出特性线了，流量被虚抬约 35%，高空推力虚高约 30%。

**做了三件事**：

1. **流量律换成换算形式**。原来"涡轮导向器壅塞决定流量"（AJE 的做法）在高空会高估，
   现在是 `ṁ = ṁ_d · (δ/√θ) · (wc(nc)/wc(nc_d))`，涡轮壅塞降级成上限保护。
2. **换算转速调节器**。功平衡解出的压比先换算成 `nc`，超过 105% 就锁住压比、二分反解
   T4（燃油被收回），并报 `governed`。这就是 FADEC 在高空做的事。
3. **风扇的同类限制**。风扇被夹住压比后旁路射流速度下降——这是高空推力掉得比
   `ρ` 掉得更快的那一截。简单模式同步加了这条。

**两个温度口径的坑**（都踩过）：

- 核心转速的 θ 要用**风扇加热后的核心进口温度** `Tt2`，不是来流温度。用错会让 N2 报成 94% 而不是 101%。
- 判据里的 θ：N1 用 `Tt1`，N2 及以后用 `Tt2`。用静温会把 11 km 的换算转速虚报成 115%，凭空刷一片 FAIL。
- 站 1 的 `T1` 在两种模式里都必须是**总温**，否则同一份判据代码在两种模式下给出不同结论。

**改完的实测（JF-1 2-spool，1970s）**

| 状态 | 残酷 kN | 简单 kN | 偏差 | 换算 N1 | 换算 N2 |
|---|---|---|---|---|---|
| 0 km M0 满油门 | 83.6 | 82.6 | −1.2% | 100% | 94% |
| 0 km M0.85 | 55.7 | 61.2 | +10.0% | — | — |
| 6 km M0 | 49.2 | 42.5 | −13.7% | 105% | 100% |
| 11 km M0 | 25.8 | 21.1 | −18.3% | 105% | 106% |
| 11 km M0.85 | 22.8 | 19.1 | −16.5% | 105% | 106% |

11 km 那行现在被调节器压到 `T4=1469 K`（指令 1500 K）、风扇压比夹到 1.66——
**这正是真机在高空推不满的原因**，不是缺陷。

判据那边同期修了两条：叶尖马赫改成**叶尖线速度**（设计转速按海平面声速定，
用当地声速会在 11 km 刷一片假 FAIL）；`evaluate()` 支持 `alt=` 自动取环境压力，
不再让 `p_amb=0` 把喷管判据静默跳过。

## 8. KSP 落地架构

### 8.1 接在哪个框架上

选 **SolverEngines**（KSP-RO/NathanKell，LGPL）。它是官方的"引擎模块 / 求解器分离"框架，
本机 GameData 里没有，需要作为依赖声明。

```csharp
[assembly: KSPAssemblyDependency("SolverEngines", 1, 0)]

public class ModuleJetForgeEngine : ModuleEnginesSolver
{
    protected override EngineSolver CreateEngine() => new JetForgeSolver();
}

public class JetForgeSolver : EngineSolver
{
    public override void CalculatePerformance(double airRatio, double commandedThrottle,
                                              double flowMult, double ispMult) { ... }
    public override double GetThrust() { ... }
    public override double GetIsp() { ... }
}
```

`ModuleEnginesSolver` 派生自 `ModuleEnginesFX`，所以 KSP 的推力/油耗/特效管线全部复用，
我们只需要把 `CalculatePerformance` 填上 §3.2 的算法。

`EngineSolver` 提供 `SetFreestreamAndInlet(...)`，把来流和进气道状态喂进来；
`EngineThermodynamics` 工具类已经实现了 §2 里大部分热力学过程（`AdiabaticProcessWithWork`、
`AddFuelToTemperature`、`CalculateMassFlow`、`ChokedPressure`），可以直接用。

### 8.2 性能策略（关键工程问题）

每个物理帧跑 40 次迭代的求解器是可行的，但没必要。方案（已在原型里跑通，见 §7.5）：

1. **编辑器里**：几何一变就重算设计点（毫秒级），实时刷读数
2. **发射/载荷变化时**：预计算一张 `(高度 × 马赫 × 油门)` 的性能表（原型用的 6×9×5 = 270 点，
   残酷模式 0.2 s；正式版可以拉到 16×12×11）
3. **飞行中**：三线性插值查表，每帧 O(1)
4. 插值结果再叠加进气道状态（KSP 的进气量）做一次薄修正

这样既保精度又不掉帧。表放在 `ConfigNode` 里跟着飞船存，跨版本自动失效重算。
**简单模式的价值就在这**：270 点建表 0.0 s，玩家改一次参数就能立刻重出整张图；
残酷模式 0.2 s 也不算慢，但玩家频繁试错时能感觉到。

### 8.3 几何怎么给玩家

两条路，建议先走后一条：

- **完整程序化建模**：自写 `PartGeometry` 风格的网格生成，玩家拉控制点出形状。工作量大。
- **B9PartSwitch / 分段预制件**：把发动机拆成"进气道 / 风扇 / 压气机 / 燃烧室 / 涡轮 / 加力 / 喷管"
  若干段，每段给 2–3 个尺寸档，拼起来的外观用 `MODEL` 节点组合。玩家能"看出来"自己拼了什么，
  数值上等价于参数化。**先做这个能快速验证玩法**。

### 8.4 与本机已有 mod 的关系

| 本机已装 | 影响 |
| --- | --- |
| FerramAerospaceResearch | 我们只算发动机内部循环，外流交给 FAR，不冲突 |
| RealFuels | 需要走 `ModuleEnginesRF` 系的燃料接口；**一阶段先不接**，用原生 `IntakeAir`+`LiquidFuel` |
| B9PartSwitch | 正好用来做 §8.3 的分段拼装 |
| KSPCommunityFixes | 无影响 |
| Waterfall | 排气特效可挂在 `ModuleEnginesFX` 的 `effectName` 上，不用改 |

### 8.5 大气模型映射

KSP 的 Kerbin 大气不是地球。求解器内部按真实 ISA 算，但要给 KSP 一个"等效高度"：

```
等效高度 h_eff = ISA 反解( KSP 当地静压 p_ksp )
```

这样同一台发动机在 Kerbin 上的推力随高度变化曲线仍然符合真实规律，
而不会出现"1 万米推力比地面还大"的怪现象。
